MMCONFIG/PCI Configuration Inventory
====================================

Legacy Configuration Entry Points
---------------------------------

* `HalpPhase0GetPciDataByOffset` — `hal/arch/i386/legacy/bus/pcibus.c:589`
  * Implements PCI Configuration Mechanism #1 (CF8/CFC port IO).
  * Callers:
    * `hal/arch/i386/acpi/halacpi.c:1933,2012,2042,2053` — ACPI HAL phase-0 PCI enumeration and BAR sizing logic.
    * `hal/arch/i386/generic/kdpci.c:103,255` — kernel debugger PCI probing and debug device configuration.

* `HalpPhase0SetPciDataByOffset` — `hal/arch/i386/legacy/bus/pcibus.c:658`
  * Same mechanism #1 writer; mirrors the read path.
  * Callers:
    * `hal/arch/i386/acpi/halacpi.c:1927,1939` — BAR probing during phase-0 enumeration.
    * `hal/arch/i386/generic/kdpci.c:82,98,108,186` — debugger BAR length discovery and command register updates.

High-Level PCI Config Helpers
-----------------------------

* `HalpReadPCIConfig` / `HalpWritePCIConfig` — `hal/arch/i386/legacy/bus/pcibus.c:478` / `:516`
  * Wrap `HalpPCIConfig` dispatch; today this ultimately hits the mechanism #1 handlers.
  * Widely used by bus management:
    * Core PCI bus enumeration (`hal/arch/i386/legacy/bus/pcibus.c` — slot validation, bridge scanning, resource assignment).
    * Legacy bus support shim (`hal/arch/i386/legacy/bussupp.c`) for HAL PCI/PCI-to-PCI bridge setup.
    * ACPI PCI bus emulation layer (`hal/arch/i386/acpi/busemul.c`) via fake bus handler cloning.

* `HalpGetPCIData` / `HalpSetPCIData` — `hal/arch/i386/legacy/bus/pcibus.c:728` / `:811`
  * Exported through `HalpFakePciBusHandler` and `HalpBusHandler` structures; consumed by higher HAL layers and bus drivers.
  * Ultimately rely on `HalpRead/WritePCIConfig`, inheriting the same CF8/CFC access path today.

Config Handler Infrastructure
------------------------------

* `PCIConfigHandler` — global dispatch table in `hal/arch/i386/legacy/bus/pcibus.c` selecting Type 1 vs Type 2 handlers.
  * Type 1 read/write helpers (`HalpPCIReadU{char,short,long}Type1`, etc.) are the only populated implementation on x86/x64.
  * `HalpInitializePciStubs` (`hal/arch/i386/acpi/halacpi.c:1999` → `hal/arch/i386/legacy/bus/pcibus.c:2120`) seeds the handler before enumeration.

Miscellaneous Direct Users
--------------------------

* Kernel debugger PCI helpers (`hal/arch/i386/generic/kdpci.c`) rely exclusively on the phase-0 get/set routines.
* Any additional consumers should go through `rg "HalpReadPCIConfig"` / `rg "HalpGetPCIData"`; current hits are limited to the modules listed above.

Implication for MMCONFIG
------------------------

Every symbol above must support ECAM-backed accesses. Adding MMCONFIG requires:

1. MMIO-aware implementations of the phase-0 get/set helpers.
2. Updating the config handler dispatch so `HalpRead/WritePCIConfig` choose ECAM when available, ensuring downstream callers (legacy bus support, fake bus handler, KD) automatically benefit.
