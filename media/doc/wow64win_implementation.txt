OVERVIEW
--------
This document describes the implementation of wow64win.dll, the Win32k
thunking layer for ReactOS WOW64 subsystem. This layer enables 32-bit
GUI applications to run on 64-bit ReactOS by translating NtUser*/NtGdi*
syscalls between 32-bit and 64-bit formats.

ARCHITECTURE
------------
WOW64 consists of three main DLLs:

1. wow64.dll     - NT* syscall thunking (kernel32/ntdll layer)
2. wow64cpu.dll  - CPU context management and transitions
3. wow64win.dll  - Win32k syscall thunking (USER32/GDI32 layer) **NEW**

Syscall Flow:
    32-bit App → USER32 → syscall → wow64cpu.dll
                                     ↓
                              wow64win.dll (convert 32→64)
                                     ↓
                              64-bit win32k.sys
                                     ↓
                              wow64win.dll (convert 64→32)
                                     ↓
                              32-bit App

CURRENT STATUS
--------------

**GUI BLOCKING INTENTIONAL**

All thunk functions currently return STATUS_NOT_IMPLEMENTED. This is
intentional to:

1. Prevent GUI processes from crashing until layer is complete
2. Allow console applications to continue working via wow64.dll
3. Provide foundation for incremental implementation

When Wow64LdrpLoadWow64Win() returns STATUS_NOT_IMPLEMENTED, the loader
gracefully blocks GUI thread initialization with an appropriate error message.

KNOWN LIMITATIONS

Current implementation limitations:

3. No Callback Thunks: Window procedures not yet thunked

These will be addressed in future milestones.

DESIGN DECISIONS
----------------

1. Structure Layout Compatibility
   - MSG32, CREATESTRUCT32, WINDOWPOS32 match Windows WOW64 exactly
   - This ensures binary compatibility with Windows applications

2. Handle Translation
   - Handles are index-based in win32k, so no conversion needed
   - Simply cast between 32-bit and 64-bit handle types

3. Pointer Validation
   - All 32-bit pointers validated before dereferencing
   - Return STATUS_INVALID_PARAMETER on validation failure

4. Error Handling
   - Return proper NTSTATUS codes (not BOOL or HRESULT)
   - Propagate kernel errors back to 32-bit caller

5. Debug Tracing
   - Comprehensive debug output for all thunks
   - Conditional compilation with DBG flag

6. Incremental Implementation
   - Stub all thunks with STATUS_NOT_IMPLEMENTED
   - Implement by category (window station, message loop, etc.)
   - Test each category before moving to next
