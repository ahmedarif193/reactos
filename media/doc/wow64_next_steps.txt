ReactOS AMD64 WoW64 – Upcoming Work
===================================

Kernel & Executive
------------------
- Complete `Wow64cpuExecuteCompatApc` so it swaps into x86 mode, executes the queued routine, and returns through `CpupReturnFromSimulatedCode` while preserving trap frames.
- Update trap/exception flow (`KiDispatchException`, user-call exit stubs) to detect WOW64 threads and redirect faults into wow64.dll instead of bugchecking.
- Ensure process/thread creation seeds PEB32/TEB32 plus loader parameters, and that teardown clears the WOW64 state cleanly.
- Finalise WOW64-aware context APIs (kernel `PsWrapApcWow64Thread`, user `NtGet/SetContextThread`) for 32-bit callers riding on 64-bit threads.

wow64cpu.dll
------------
- Port the AMD64↔x86 register shuffle assembly used by callbacks and exception dispatch (`CpupDoCallBack`, `CpupDispatchException`).
- Manage FP/XMM context synchronisation across transitions.
- Add DBG-gated tracing so early LiveCD runs can diagnose transition bugs.

wow64.dll
---------
- Expand bootstrap to drive CSR/LPC startup, KnownDLL resolution, and environment setup from `\Windows\SysWOW64`.
- Implement the minimal syscall thunk table for console apps (`NtOpenFile`, `NtReadFile`, `NtWriteFile`, `NtQueryInformationProcess`, `NtQuerySystemInformation`, etc.).
- Wire TLS helpers and APC delivery so 32-bit ntdll can queue and drain APCs reliably.
- Provide fallback stubs with logging for unimplemented thunks to avoid silent hangs.

GUI / Win32k (follow-up milestone)
----------------------------------
- Introduce wow64win.dll with enough USER32 thunks for window station/desktop and message loop bring-up, or explicitly block GUI processes until the layer is ready.
- Translate win32k packets (handles, shared info) between 32/64-bit layouts.

Packaging & Boot Media
----------------------
- Finalise dual KnownDLL lists in the boot hives (System32 vs SysWOW64) and include wow64 modules in CAB manifests.
- Mirror 32-bit binaries, wow64*.dll, and required SxS assemblies into `reactos/SysWOW64` for bootcd/livecd targets.
- Keep developer artifacts (.pdb/.lib/.map/etc.) out of the SysWOW64 tree during packaging.

Testing & Automation
--------------------
- Integrate the new `wow64smoke.exe` into LiveCD boot scripts or documentation as the first user-mode validation step.
- Extend rostests/winetests with a minimal 32-bit suite that runs under WOW64 once the syscall path stabilises.
- Build a CI VM scenario: boot amd64 LiveCD, run `wow64smoke.exe`, and report success/failure to gate regressions.

Documentation & Diagnostics
---------------------------
- Keep `wow64_roadmap.txt` aligned with implementation progress; prune completed items and add new blockers as they appear.
- Add developer notes on enabling/disabling WOW64 tracing so debuggers know how to capture transition logs.
