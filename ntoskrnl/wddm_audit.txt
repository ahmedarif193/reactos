1. IoLoadDriver(PUNICODE_STRING DriverServiceName)
   Status: [ADD]
   Spec entry added:  ntoskrnl/ntoskrnl.spec line 456
   Implementation:    ntoskrnl/io/iomgr/driver.c (new function, calls IopDoLoadUnloadDriver)
   Notes: Kernel-mode variant of NtLoadDriver; skips privilege check.
          dxgkrnl actually uses ZwLoadDriver (which was already exported) rather than
          IoLoadDriver directly, but IoLoadDriver is part of the documented KMI and
          needed for completeness. Wraps IopDoLoadUnloadDriver which handles correct
          system-process context for MmLoadSystemImage.

12. PsSetCreateProcessNotifyRoutineEx
    Status: [ADD]
    Spec entry added:  ntoskrnl/ntoskrnl.spec line 1054
    Implementation:    ntoskrnl/ps/psnotify.c (new function)
    Supporting changes:
      - ntoskrnl/ps/psnotify.c: added PspProcessNotifyRoutineEx[] array and
        PspProcessNotifyRoutineExCount global
      - ntoskrnl/ps/psmgr.c: initialize PspProcessNotifyRoutineEx[] slots
      - ntoskrnl/include/internal/ps.h: extern declarations for new globals
      - ntoskrnl/include/internal/ps_x.h: new PspRunCreateProcessNotifyRoutinesEx()
        inline dispatcher
      - ntoskrnl/ps/process.c: call PspRunCreateProcessNotifyRoutinesEx on create
      - ntoskrnl/ps/kill.c: call PspRunCreateProcessNotifyRoutinesEx on exit
    Notes: dxgkrnl.sys registers DxgkProcessCleanup via this API to track GPU
           handles when processes exit without calling D3DKMTCloseAdapter first.
           The Ex variant passes PS_CREATE_NOTIFY_INFO (non-NULL for creation,
           NULL for termination) rather than the legacy (ParentPid, Pid, BOOL)
           triple. The implementation uses a dedicated separate slot array
           (PspProcessNotifyRoutineEx) to avoid type confusion with legacy slots.
           TODO: Populate ImageFileName and CommandLine in process.c from the
           section/PEB once NtCreateUserProcess is fully integrated.
