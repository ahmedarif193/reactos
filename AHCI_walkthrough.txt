AHCI BOOT DEBUG WALKTHROUGH
===========================

Repro & Tooling
---------------
- Build + boot via `./symbolize_stack.py` (rebuilds, runs QEMU, captures serial/kdbg output).
- Inspect `output-MinGW-amd64-Debug/logs/` for the latest serial dump when QEMU halts.

Chronology & Checklist
----------------------

[Baseline]
- [x] Captured the original boot log ending in `INACCESSIBLE_BOOT_DEVICE (0x7B)` after storport enumerated the AHCI controller.
- [x] Logged AHCI init path: controller reported 6 ports, port 0 IDENTIFY OK, other ports timeout, ending with storport returning 0 devices -> 0x7B (log excerpt 0xFFFFF880042AD8C0...).

[Instrumentation and Enumeration]
- [x] PartMgr instrumentation (drivers/storage/partmgr/partmgr.c): log IoReadPartitionTableEx status, return DEVICE_RELATIONS, create `\Device\Harddisk0\Partition1` symlink once PDO starts.
- [x] Storport enhancements (drivers/storage/port/storport/):
      • Cache READ CAPACITY(10/16) data per PDO and serve IOCTL_DISK_* queries from the cache.
      • Refresh cache on SRB completions.
      • Publish geometry/length/device-number through `PortDispatchDeviceControl`.
- [x] Guarded the storport device-property IOCTL path so short METHOD_BUFFERED buffers only receive the header, preventing overwrites of the classpnp debug guards.
- [x] Re-enabled the legacy PCI IDE stack (pciide/pciidex/atapi) so boot-time PnP can enumerate parallel ATA alongside AHCI for regression coverage.
- [x] Subdivide AHCI SRBs so each transfer ≤128 KiB, keeping PRDT ≤32 entries (prevents controller rejecting requests during boot).
- [x] Added detailed logging for READ CAPACITY / INQUIRY flows to confirm enumeration survives into user mode.

[Build Status]
- [x] `ninja` (output-MinGW-amd64-Debug) builds cleanly after storport updates.
- [x] Latest edits include fixing `RtlCompareMemory` for AMD64 (`sdk/lib/rtl/amd64/rtlmem.S`: use `cld` instead of the accidental `cli`).

[Current Behavior]
- [x] QEMU boot now proceeds past storport; `umpnpmgr!PnpEventThread` eventually triggers `BAD_POOL_HEADER (0x19)` in `nt!ExpCheckPoolHeader` (still under investigation, see Outstanding).
- [x] Storport no longer scribbles past METHOD_BUFFERED IOCTL buffers: device-property queries respect small output lengths, and the classpnp guard allocator stays quiet through repeated boots.
- [ ] Long-run stability beyond early PnP bring-up remains unverified; current 3-minute headless boots show continuous AHCI IO but still hit the legacy pool-corruption path.
- [x] Instrumented the PnP device-action queue (`ntoskrnl/io/pnpmgr/devaction.c`) with guard signatures around each queued request to catch the point of memory corruption (security check failure was firing when list links were smashed).
