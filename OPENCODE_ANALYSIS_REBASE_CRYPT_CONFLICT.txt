RESOLUTION
----------
DROP (accept HEAD, discard incoming).

The incoming hunk is purely cosmetic formatting of code that HEAD has
already intentionally removed. Preserving/adapting the incoming SEH
blocks would:
  - Create orphaned _SEH2_EXCEPT blocks with no matching _SEH2_TRY
  - Cause compilation errors
  - Reintroduce an SEH wrapping pattern incompatible with the new
    key_from_handle/hash_from_handle validation approach

The correct resolution is to accept the HEAD side (no SEH blocks)
and discard the incoming `#ifdef __REACTOS__` _SEH2_EXCEPT blocks
from all 3 conflicted functions.
