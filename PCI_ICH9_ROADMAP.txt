ReactOS PCI / HAL / xHCI Roadmap for ICH9/Q35
=============================================

Goals
-----
- Match Windows 7/10 behavior on Intel ICH9/Q35 (including VirtualBox emulation).
- Use ECAM/MMCONFIG only when firmware actually decodes it; otherwise use legacy CF8/CFC.
- Always deliver a valid interrupt (GSI or MSI) to xHCI and storage controllers.
- Enable MSI/MSI-X on real hardware; tolerate legacy-only operation on VBox.


Phase 1 – ECAM handling parity (ICH9/Q35 vs real HW)
----------------------------------------------------

1. Tighten VirtualBox ECAM detection
   - In `hal/arch/common/acpi/halacpi.c`:
     - Use `HalpAcpiIsVirtualBoxMcfg` + OEM IDs to classify VBox MCFG as broken.
     - For that case only:
       - Set `HalpAcpiEcamDisabled = TRUE` as soon as the VBox probe fails (vendor=0xFFFF).
       - Skip further MMCONFIG vendor probing and rely exclusively on legacy CF8/CFC config.
   - For non-VBox MCFG tables:
     - Keep the vendor probe between `FirstAllocation->BaseAddress` and the mapped page.
     - Only disable ECAM for the affected segment if the vendor read is all ones and `HalpPciVendorIdLooksSane` rejects it.

2. Avoid ECAM use in debug walker once disabled
   - In `HalpAcpiEnumeratePciBusDebug`:
     - Check `HalpAcpiEcamDisabled` before calling `HalpPhase0GetPciDataByOffset`.
     - If disabled, do not attempt `HalpAcpiAccessConfigEcam` at all; read config space via CF8/CFC only.
   - This removes repeated "ECAM requested after ECAM was globally disabled" noise while matching actual runtime behavior.

3. Keep stub implementations consistent
   - In `hal/arch/i386/legacy/acpi_ecam_stubs.c` and `hal/arch/i386/minihal/acpi_ecam_stubs.c`:
     - Always define `HalpAcpiEcamDisabled = TRUE`, as these HALs never support real ACPI/MMCONFIG.
   - Ensure there is a single definition of `HalpAcpiEcamDisabled` per build and no conflicting initialization between the stubs and the common ACPI path.


Phase 2 – IRQ routing and “Failed to satisfy interrupt requirement”
-------------------------------------------------------------------

4. Fix IRQ requirement construction in the PCI bus driver (PCI PDO)
   - In `drivers/bus/pci/pdo.c` (StartDevice / resource publication):
     - Compare against WDK patterns (use `/home/ahmed/WorkDir/TTE/winsdk-10` WDM headers for `CM_PARTIAL_RESOURCE_DESCRIPTOR`, `IO_RESOURCE_DESCRIPTOR`).
     - Ensure for PCI devices:
       - `ShareDisposition = CmResourceShareShared`.
       - `Flags = CM_RESOURCE_INTERRUPT_LEVEL_SENSITIVE`.
       - Do not hard-code narrow IRQ ranges (e.g. 0x9–0x9) unless the ACPI/BIOS truly requires it.
     - For all PCI functions (including xHCI):
       - Request a *range* of interrupt vectors (0..0xFF) as today, but ensure this does not artificially constrain HAL/ACPI routing. Do not encode a fixed 0x9–0x9 range in the PCI PDO.

5. Route PCI GSIs using ACPI _PRT data
   - In `drivers/bus/acpi/busmgr/acpi_pci_routing.c` and `hal/arch/common/legacy/bus/pcibus.c` (`HalpSetPciRoutingMap`):
     - Validate that each PCI INTx pin (segment/bus/dev/function/pin) maps to a GSI using _PRT entries and link devices.
     - Add debug logs for each route:
       - "segment:bus:device.fn INTx -> GSI N (polarity=..., trigger=...)".
     - Ensure the PCI PDO’s interrupt resource requirements are compatible with these routes (i.e. they request a range that actually includes the mapped GSI).

6. Adjust PnP interrupt resolver to choose valid GSIs (PnP core)
   - In `pnpres.c` interrupt allocation logic:
     - When an interrupt requirement conflicts (e.g. 0x9–0x9 or 0xa–0xa already in use):
       - Treat level‑sensitive line interrupts as shareable when the requester asks for `CmResourceShareShared`, even if a previous claimant did not mark the vector shared (Windows‑compatible PCI/APIC behaviour on ICH9/Q35).
       - Keep non‑shared and edge‑triggered interrupts non‑shareable to avoid hiding real conflicts.
       - If sharing is still not allowed, search for another GSI compatible with the device’s ACPI routing rather than failing outright.
     - Implemented: `IopCheckResourceDescriptor` now allows shared level‑sensitive IRQs to reuse an existing vector; follow‑up work is to add smarter GSI selection when firmware exposes multiple candidates.


Phase 3 – MSI/MSI‑X for xHCI (long-term, real ICH9)
---------------------------------------------------

8. Expose MSI/MSI‑X interfaces from the PCI bus driver
   - Using `/home/ahmed/WorkDir/TTE/winsdk-10/Include/10.0.16299.0/km/wdm.h` as reference (e.g. `PCI_MSIX_TABLE_CONFIG_INTERFACE`, MSI APIs):
     - Implement MSI/MSI‑X query/set interfaces in the PCI FDO (`drivers/bus/pci/fdo.c`).
     - Publish them to child drivers via the BUS_INTERFACE_STANDARD or a PCI-specific interface.

9. Add MSI message resources for MSI‑capable functions
   - In `drivers/bus/pci/pdo.c`:
     - For devices with an MSI or MSI‑X capability and where FADT does not disable MSI:
       - Build `CM_RESOURCE_INTERRUPT_MESSAGE` descriptors in addition to (or instead of) legacy line interrupts.
       - Reflect the MSI vector and affinity in the translated resource list.
   - Ensure that both storport (AHCI) and usbxhci can receive message-based interrupts when available.

10. Teach USBPORT/usbxhci to use MSI when present
    - usbport:
      - Already uses `UsbPortIoConnectInterruptEx` for message-based interrupts when `InterruptFlags & CM_RESOURCE_INTERRUPT_MESSAGE` is set.
    - usbxhci:
      - Continue to log "using message interrupts" vs "using legacy IRQ".
      - Expect to run with MSI on real ICH9 hardware; fall back to legacy IRQs when MSI is unavailable (e.g. VBox).


Phase 4 – Validation against Windows on ICH9/Q35
-----------------------------------------------

11. Capture Windows reference behavior
    - On the same ICH9/Q35 platform (or VBox config), boot Windows 7/10 and use:
      - WinDbg `!pci`, `!acpi`, `!devobj` for resource and routing inspection.
      - `devcon resources` or Device Manager for device resource lists (xHCI, AHCI).
    - Record:
      - For xHCI and AHCI:
        - Interrupt type (MSI/MSI‑X vs line-based), vector, level, share.
        - Whether MSI is enabled.
      - Global PCI routing:
        - GSI ranges, IOAPIC redirection entries, and _PRT mappings.

12. Iterative convergence
    - Adjust ReactOS HAL/PCI/ACPI behavior until:
      - No "Failed to satisfy interrupt requirement with IRQ 0x9-0x9" for PCI devices.
      - No "Resource conflict: IRQ (0xa 0xa vs. 0xa 0xa)" for xHCI/AHCI.
      - PCI debug output (`HalpDebugPciDumpBusAcpi`) matches Windows class/vendor/device decoding for ICH9 devices.
      - xHCI enumerates USB devices correctly on real ICH9 hardware.
      - Under VBox ICH9/Q35:
        - ECAM is disabled early, all config via legacy CF8/CFC, but devices enumerate and interrupts are assigned cleanly on legacy lines.
