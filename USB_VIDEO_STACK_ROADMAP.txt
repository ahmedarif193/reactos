USB Video / Newdev Roadmap
==========================

Legend:
  [ ] = planned
  [x] = completed
  [-] = partial / in-progress


Phase 0: Diagnostics & Install Infrastructure
--------------------------------------------

[x] 0.1 Fix newdev heap misuse on CustomSearchPath
    - Ensure all DevInstData->CustomSearchPath pointers owned by newdev
      are heap-allocated and freed exactly once (no stack pointers).

[x] 0.2 Harden newdev pipe / ClientSideInstallW protocol
    - Add defensive bounds checking for all lengths received over the
      umpnpmgr↔newdev named pipe (Value, strings, flags).
    - Reject malformed or inconsistent payloads with clear logging instead
      of proceeding into wizard logic.

[x] 0.3 Improve installer diagnostics for failed function installs
    - For devices where DevInstallW fails with ERROR_NO_DRIVER_SELECTED
      / ERROR_NO_SUCH_DEVINST / ERROR_FILE_NOT_FOUND, record a concise
      error + HWID/compatible IDs in the device’s registry key and debug
      log to simplify triage of missing INF/class support.


Phase 1: Basic USB Video Class Enumeration
------------------------------------------

[x] 1.1 Provide stub usbvideo.sys function driver
    - Implement minimal AddDevice / PNP / POWER plumbing for class 0x0E
      interfaces so they get a function driver and clean removal, even
      without streaming support.

[x] 1.2 Bind USB Video Class via INF
    - Add usbvideo.inf under Class=Image to match USB\Class_0E compatible
      IDs from usbccgp and install usbvideo.sys as the service.

[ ] 1.3 Verify composite/UVC enumeration with usbccgp
    - Exercise typical UVC devices (integrated webcams, USB cameras) and
      confirm:
        - usbccgp creates function PDOs for UVC interfaces.
        - usbvideo is selected as the function driver for USB\Class_0E.
        - Device Manager shows “USB Video Device” entries under the Image
          class without installer heap warnings.

[ ] 1.4 Class installer / UI integration for Image class
    - Review c_image.inf and sti_ci.dll interactions and ensure that
      Image-class devices using usbvideo show up with reasonable
      descriptions, icons, and basic properties (even if no capture yet).


Phase 2: UVC Descriptor & Topology Support
-----------------------------------------

[x] 2.1 Parse VideoControl / VideoStreaming descriptors
    - Implement descriptor parsing in usbvideo to:
        - Walk class-specific VC and VS descriptors for each interface.
        - Build an internal representation of terminals, units, and
          streaming interfaces (formats, frames, endpoints).

[x] 2.2 Export a stable internal topology model
    - Define data structures in usbvideo for:
        - Terminal graph (Camera, Processing, Output units).
        - One or more VS interfaces with supported formats (YUY2, MJPEG,
          H.264) and frame sizes/rates.
    - Align data layout and semantics with Windows 7 UVC where feasible
      to reduce surprises for user-mode stack.

[x] 2.3 Basic property handling (brightness/contrast/etc.)
    - Map standard UVC control requests onto a property abstraction that
      can later feed KS properties or a user-mode API.


Phase 3: Streaming / Data Path
------------------------------

[-] 3.1 Isochronous/bulk endpoint plumbing in usbvideo
    - Build a minimal streaming path in usbvideo:
        - Select a VS alternate setting, arm the isoch/bulk endpoint.
        - Program URBs via usbport for a continuous ring of transfers.
        - Provide a simple kernel-facing abstraction (e.g. read-like API
          or callbacks) for received payloads.

[ ] 3.2 KS / AV stack integration
    - Decide on integration strategy:
        - Either expose a KS capture filter/pins directly from usbvideo,
          or introduce a small bridge driver that maps UVC streams onto
          existing ks/kscaptur infrastructure.
    - Implement a single capture pin (uncompressed YUY2 or MJPEG) for a
      subset of UVC devices as a first target.

[ ] 3.3 Format negotiation and fallback
    - Implement basic format negotiation:
        - Prefer uncompressed YUY2 or MJPEG at a conservative resolution
          (e.g. 640x480, 30 fps) when available.
        - Provide graceful fallback when requested formats are unavailable
          instead of failing the entire device.

[ ] 3.4 Error handling and recovery
    - Handle stalled endpoints, device resets, and unplug/replug while
      streaming:
        - Abort/cleanup pending URBs on error.
        - Allow userspace or KS clients to re-open the stream without
          requiring a reboot.


Phase 4: Stability, Instrumentation, and Parity
----------------------------------------------

[ ] 4.1 End-to-end pool/IOCTL audit for UVC path
    - Re-run pool/special-pool instrumentation and SystemBuffer audits
      on:
        - usbport/usbhub/usbccgp along the VC/VS IOCTL and URB paths.
        - usbvideo UVC control/streaming IOCTLs (once added).
    - Ensure no caller-controlled lengths can overrun kernel allocations.

[-] 4.2 Improve newdev error reporting for image devices
    - When usbvideo / Image-class devices fail to install or bind, have
      newdev record a class-specific fail reason (e.g. “No UVC support”)
      using USBH_WriteFailReasonID-like logic, to aid user debugging.

[ ] 4.3 Windows 7 parity audit
    - Compare ReactOS usbvideo + usbccgp behaviour with Windows 7:
        - Descriptor parsing semantics (e.g. tolerance for malformed
          BOS/UVC descriptors).
        - Supported IOCTLs and INF matching for USB\Class_0E and common
          composite layouts.
        - Basic camera enumeration in Device Manager and ability to
          open the device via standard capture APIs.

[ ] 4.4 Extended UVC features (post-MVP)
    - Once basic streaming works, iterate on:
        - Multiple streams / alternate interfaces (e.g. still image,
          metadata).
        - H.264 / MJPEG acceleration paths where feasible.
        - Power management (selective suspend, runtime idle).
