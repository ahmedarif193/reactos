Phase 7 - ReactOS-Native Mutation Validation (2026-07-22)
---------------------------------------------------------
[x] Fix Create Partition failing with "No free primary MBR slot" on an empty
    MBR disk: ReactOS partmgr reports only the used entries, so the layout is
    now expanded to the four real primary slots before the slot search.
[x] Fix kernel partmgr allocation-size underflow (EnumeratedPartitionsTotal-1
    with zero partitions asked paged pool for 34 GB), which broke PnP
    re-enumeration whenever the last partition of a disk was deleted.
[x] Fix volume-to-region binding never working: the snapshot opened the
    \\?\Volume{...}\ path form (the filesystem root directory), which fails
    outright on RAW volumes; it now opens the volume device itself, so
    extents, device numbers, and capacities resolve (also fixed 0 B CDFS
    capacities).
[x] Replace the blocking wait for the created volume with a deferred
    pending-create record: the create action returns immediately and a timer
    applies the requested drive letter and format as soon as the volume
    device arrives (ReactOS installs it asynchronously, 3 s to minutes).
[x] Add automatic view refresh after mutating actions and WM_DEVICECHANGE,
    polling for a while because ReactOS finishes partition/volume arrivals
    and removals asynchronously and does not broadcast a completion.
[x] Fix the background timers never running after the first context menu:
    ReactOS does not always deliver WM_MENUSELECT's close notification for
    tracked popups, so bInMenuLoop stayed TRUE forever; it is now also
    cleared via WM_ENTERMENULOOP/WM_EXITMENULOOP and after TrackPopupMenuEx.
[x] Fix deleting an empty extended partition wiping the whole MBR: with the
    container gone but a stale >4 PartitionCount, the kernel's legacy table
    writer walked to a nonexistent EBR with a zero offset and rewrote sector
    0 with the empty logical table. The app now clamps the count to the four
    primary slots, and xHalIoWritePartitionTable stops when there is no next
    EBR offset (kernel hardening).
[x] Validate on ReactOS (livecd VM, AHCI disk): create primary FAT (auto
    letter + quick format), create logical drive with auto-created extended
    container (auto letter + format), delete primary, delete logical, delete
    empty extended via its free space with the primary surviving, and
    automatic view healing after every operation without manual refresh.

Phase 8 - Kernel Follow-Up Fixes (2026-07-23)
---------------------------------------------
[x] Fix kernel bugcheck 0xCA (PNP_DETECTED_FATAL_ERROR, duplicate PDO) when
    a partition is re-created with the same disk/offset/length identity as
    one removed earlier in the same boot: removed devnodes linger in the
    tree as phantoms, and PiInitializeDevNode treated the phantom as a live
    duplicate. It now retires the phantom (IopFreeDeviceNode) and lets the
    re-arrived device take over the instance path; validated with a
    same-boot create -> delete -> identical re-create completing end to end.
[x] Fix partmgr SET drive-layout handlers: free the layout copy on the
    super-floppy rejection and write-failure paths (leaks), and propagate
    the real write status instead of always returning STATUS_SUCCESS.
